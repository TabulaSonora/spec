# Documentation — Deconstructing the Sauce

Reverse-engineering **Roland SOUND Canvas VA** (`SCCore.dll`) to build a readable, embeddable
reimplementation of the synth voice. This folder collects all project documentation. It is a
preservation / interoperability effort on a discontinued product.

## The reimplementation (repo root)

- `scvx_engine.py` — the synth voice: DPCM codec, 4-tap resampler, TVA/TVF/pitch envelopes, LFO,
  pitch chain, drum kits. Built entirely from the RE'd tables (no `SCCore.dll` at render time).
- `scvx_directory.py` — patch/tone/multisample/wave-zone resolution (program+note+vel → wave).
- `scvx_partials.py` — per-partial synthesis parameter decode from the tone table.
- `scvx_sequencer.py` — the playback layer: Standard MIDI File parsing + per-part continuous
  controllers over time (CC7/CC11/CC1 mod-wheel/CC10 pan/CC64 damper, pitch bend, RPN tune, drum
  choke groups, drum-kit select).
- `tools/decoder/` — the C# `scdec` harness that drives the real DLL for A/B ground truth
  (`seq`, `holdnote`, `drum`, `tvftrace`, `lfotrace`, … modes).
- `tools/ghidra_scripts/` — the Ghidra headless scripts that produce `SCCore.decompiled.c`
  (`DecompileToC.java`) and apply the recovered function/label names (`Rename*.java`).

Three notes on running them. `DefineTableFunctions.java` must run before the naming passes: large
parts of the control path are reached only through data pointer tables, so nothing *calls* those
targets and auto-analysis never disassembles them. `RenameXg.java` must run *last* — it renames the
XG SysEx front end, which the earlier passes had named as if it were GS. And **no address may be
named by two scripts**: the later one silently wins, so the result depends on run order.
`RenameSynth`/`RenameLfo` (`18008fbb0`), `RenameSynth`/`RenameEnvSeg` (`180060ca0`) and
`RenameDispatch`/`RenameBulk2607` (`1819a7a00`) each had that collision; the duplicate side is now
commented out with a note pointing at the owner.

Any script that writes table dumps — `Export*.java`, `RenameEnvSeg.java`, `RenameLfo.java` — takes
the output directory as its first script arg or from `$SCVX_TABLES_DIR`, defaulting to `tables/`
relative to the working directory and creating it if missing. The two `Rename*` ones treat the dump
as best-effort so a failed write cannot cost you their renames.

## Reference data

- `SCCore.decompiled.c` — the Ghidra decompile (~84k lines). Regenerated by
  `tools/ghidra_scripts/DecompileToC.java` after each renaming pass; kept named as RE progresses.
- `tables/` — static tables exported from the DLL `.rdata` (curves, LFO/interp/pan tables).
